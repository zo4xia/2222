## 各环节法度（入参 · 出参 · 产出物 · 规则 · 价值）

### Step 0：Agent A 识别（题目 → handoff）

| 维度 | 规格 |
|---|---|
| **入参** | 用户上传的题目图片 / 文本 |
| **出参** | `handoff` payload：`{problemText, problemType, boardPlan, zoneAnchors, canvasParams, knowledgeAnalysis, stageRatioSuggestion, ...}` |
| **产出物** | handoff JSON 文件（Agent B 唯一真相源） |
| **规则** | 画布参数唯一真源 = `stepHandoff.js`；坐标系统 = 百分比 0—100；不传原图/网格快照 |
| **价值** | 为下游提供题目事实、题型指南、布局规划和画布基准——没有它下游全是盲猜 |

**关键衔接点**：`boardPlan` 的四区坐标（question/analysis/solution/summary）是 Step 4 落点排版的区域输入。Step 0 定的布局 → Step 4 继承 → 板书不歪。

---

### Step 1：Agent B 生成（handoff → 五字段行表）

| 维度 | 规格 |
|---|---|
| **入参** | handoff payload + system prompt（prompt.js + 选定 skill 的规则） |
| **出参** | `{rows: [{stage, speech, board:{content, startDelay}, actionSpec}]}` |
| **产出物** | JSON 行表（每行 = 一个完整教学时刻） |
| **规则** | stage 仅限题目/分析/解答/总结；board 只输出 content + startDelay，不输出坐标；speech 是纯口播文本无 TTS 标签；actionSpec 工具白名单 = rough-notation/line/arrow |
| **价值** | 把教学意图翻译成程序可执行的五字段——教学灵魂在这里，程序只是执行者 |

**board-lecture skill 注入提示词**：当 Agent B 选中 `board-lecture` skill 时，`buildSystemPrompt()` 返回 6 步规范全文，指导 LLM 输出符号规范的 board.content。

---

### Step 2：Contract 归一化（行表 → 规范化行表）

| 维度 | 规格 |
|---|---|
| **入参** | `rows`（LLM 原始输出） |
| **出参** | `rows`（board 统一为 `{content, startDelay}` 对象） |
| **产出物** | 归一化行表 + 弃用字段警告列表 |
| **规则** | `normalizeBoard()` 处理字符串/对象/数组三种 board 格式；弃用字段（startCoord/triggerAt/durationMs/seed）自动剥离并生成 `_deprecationWarning` |
| **价值** | 消除 LLM 输出的格式分叉——不管模型输出什么变体，到这一步统一为干净对象 |

**文件**：`src/agent-b-v2/contract.js`
**JSON 解析真源**：`src/lib/parseLLMJson.js`（6 处调用统一引用，不再手搓）

---

### Step 3：板书排版标准化 ★本次新增（board-lecture skill）

这是当前管线最薄弱的一环，本次补齐。三个纯函数串联执行：

#### 3a. 符号规范化

| 维度 | 规格 |
|---|---|
| **入参** | `content: string` |
| **出参** | `{ result: string, changes: Array<{from, to, count}> }` |
| **产出物** | 规范化 board.content + 变更审计日志 |
| **规则** | 20 条 LaTeX→Unicode 替换（长匹配优先）；`\div→/`、`\triangle→三角形`、`\therefore→因此`（与 prompt 规范对齐） |
| **价值** | LLM 不可控时兜底——即使模型输出 `\times`，到这里自动变成 `x` |

**策略文件**：`src/agent-b-v2/skills/board-lecture/lib/normalizeSymbols.js`
**运行时真源**：`src/utils/superFilter.js#normalizeBoardLine`（10 步流水线，更完整，含 HTML 解码 + LaTeX 损伤修复 + aligned 剥壳）

> 二者关系：normalizeSymbols 是策略规格（给 prompt 引用 + Check Agent 预审），superFilter 是渲染层执行（实际写入画布前的清洗）。行为保持一致，有冲突以 superFilter 为准。

#### 3b. 容量估算

| 维度 | 规格 |
|---|---|
| **入参** | `{ content, regionWidth(px), fontSize(px), lineHeight }` |
| **出参** | `{ charCount, charsPerLine, lineCount, totalHeight(px) }` |
| **产出物** | 文本占多少行、多高 |
| **规则** | 默认值来自 stepHandoff.js（fontSize=38, lineHeight=1.7）；charsPerLine = `floor(regionWidth / fontSize)` |
| **价值** | 在渲染前就知道内容会不会溢出——不需要等画布渲染后才发现挤不下 |

**文件**：`src/agent-b-v2/skills/board-lecture/lib/estimateCapacity.js`
**区域宽度来源**：`boardLayout.js#BOARD_LAYOUT` 的 `zone.w`（百分比）× `CANVAS_W`（1726px）

#### 3c. 布局决策

| 维度 | 规格 |
|---|---|
| **入参** | `{ capacity, regionHeight(px), hasMultipleSteps }` |
| **出参** | `{ action: 'normal'|'compact'|'twocolumn'|'overflow', fontSize, reason }` |
| **产出物** | 字号决策 + 布局模式 + 原因 |
| **规则** | 四级优先级不可跳级：normal(38px) → twocolumn(36px两列) → compact(36px) → overflow(36px+精简) |
| **价值** | 自动降级——内容多时自动压缩字号或分栏，不需要人工调 |

**文件**：`src/agent-b-v2/skills/board-lecture/lib/decideLayout.js`

---

### Step 4：落点排版（规范化行表 → 像素坐标）

| 维度 | 规格 |
|---|---|
| **入参** | `rows: Array<{stage, board:{content}}>, {fontSizePx}` |
| **出参** | `Array<{startCoord, x, y, lineCount}>` |
| **产出物** | 每行板书的像素级落点 |
| **规则** | 起点 = 区域左上角；纵向游标单调递增 → 天然不重叠；触底即停 |
| **价值** | 把抽象的"分析区第一行"变成"[6%, 41%]"的具体坐标 |

**文件**：`src/utils/boardLayout.js#layoutBoardRows`

**衔接 Step 0**：`BOARD_LAYOUT` 的四区坐标来自 Step 0 的 handoff `boardPlan`（或默认布局）。Step 0 定区域 → Step 4 在区域内排版。

**衔接 Step 3c**：decideLayout 返回的 `fontSize` 可传给 layoutBoardRows 的 `fontSizePx` 参数，实现自动字号压缩。

---

### Step 5：渲染清洗（板书文本 → 手写体可渲染文本）

| 维度 | 规格 |
|---|---|
| **入参** | `boardLine: string` |
| **出参** | `string`（清洗后，手写体可直接渲染） |
| **产出物** | 干净的板书文本行 |
| **规则** | 10 步流水线顺序不可倒：`\n`还原 → 控制字符退化 → HTML解码 → LaTeX损伤修复 → aligned剥壳 → 删$ `\left` `\right` → 手写体降级 → LaTeX→Unicode → 角标 → 压空白 |
| **价值** | LLM 输出什么 LaTeX 残渣都能洗干净——渲染层永远收到纯文本 |

**文件**：`src/utils/superFilter.js#normalizeBoardLine`

---

### Step 6：时间线编排（行表 → 毫秒排期）

| 维度 | 规格 |
|---|---|
| **入参** | 单行 `row`（含 speech + board + actionSpec） |
| **出参** | `{ exclusiveExecutionPlan, actionTimeline, ... }` |
| **产出物** | 毫秒级排期表（板书/动作互斥） |
| **规则** | 单手一维时间线；板书写完后动作才能开始；标点停顿 = 动作执行窗口；口播 160字/分；行间 1.5s gap |
| **价值** | 把"先讲后写"变成"<1230ms 开始写第 1 行，<2890ms 画箭头"——画布执行器只管按排期跑 |

**文件**：`src/agent-b-v2/timing.js#computeRowGroupTimeline`

---

### Step 7：画布渲染（排期 → 最终画面）

| 维度 | 规格 |
|---|---|
| **入参** | exclusiveExecutionPlan + actionTimeline + handoff.canvasParams |
| **出参** | 视频画面（逐行渐显书写 + 动作绘制 + 语音同步） |
| **产出物** | 最终白板讲题画面 |
| **规则** | rough.js 画线/箭头/图形；rough-notation 画下划线/高亮/圈出；手写体 CSS = 平方乔木体 CDN 507；不引入额外绘图框架 |
| **价值** | 全管线的终点产出——孩子看到的是这一帧 |

**技术栈**：`rough.js` + `rough-notation` + KaTeX（仅真分数 `\frac`）+ 手写体 CSS

---

## 法度总纲（五条铁律）

1. **一次只写一处** — 板书与动作绝对互斥，单手一维时间线
2. **板书字不能小** — 正常 38px，最低 36px
3. **分析区红色** — 分析板书红色，解答/总结黑色
4. **排版紧凑** — 不留空洞，溢出时优先压缩字号，最后才精简内容
5. **只画题目要求的内容** — 不添加答案、不画示意以外的图形
